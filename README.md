# Inev

**Inev** is not just an encryption tool; it is a **data reconstruction engine**. It allows you to "hide" files by deconstructing them into a series of mathematical coordinates that point to data already existing in other files on your system (Videos, ISOs, Games, etc.).

The result is a **Map File** that contains zero bytes of your original secret, making it technically impossible to recover without both the **Map** AND the original **Carrier Files**.

> **Release note:** Starting with v4, the map uses **AES-256-GCM**. Maps generated by earlier versions (CBC) cannot be decrypted by the current build—please regenerate them.


---

### 1. Inverted Indexing & Carrier Streaming (Sliding Window)
Inev features a high-performance **Inverted Suffix Tree Architecture** combined with a **Sliding Window Carrier Streamer**:
*   **Secret-Indexed Suffix Tree:** Instead of building massive index trees for gigabyte-sized carrier files, Inev indexes the **Secret** in an Ukkonen-based Suffix Tree.
*   **Constant Memory Footprint ($O(\text{Secret})$ RAM):** Carrier files are read sequentially in 8MB chunks via sliding window. Memory consumption depends solely on the secret's size, allowing you to scan **100GB+ ISOs/Videos with <100MB of RAM**.
*   **$O(1)$ Direct Coordinate Lookup:** The Suffix Tree directly yields exact byte offsets in $O(1)$ time, eliminating linear pattern searching.
*   **Data Pointer System:** The generated map stores coordinate tuples: `[Secret_ID, Carrier_ID, Offset, Length]`.

---

### 2. Chameleon Multi-Secret System
You can map **multiple secrets** (e.g., a PDF, a ZIP, and a Key) into a **single map file**. 
*   **Selective Recovery:** If you only provide some of the carriers to the decoder, only the secrets that "belong" to those carriers will be reconstructed. The others remain invisible/corrupted.

---

### 3. Security & Integrity Architecture
*   **Encryption:** AES-256-GCM (AEAD, authenticated).
*   **Key Derivation:** PBKDF2-HMAC-SHA256 with **600,000 iterations** and a unique random salt.
*   **Randomness:** Nonce de 12 bytes unique per map, genarated by `RAND_bytes`.
*   **Compression:** The entire map is Zlib-compressed before encryption to minimize size and eliminate data patterns.
*   **SHA-256 Carrier Verification:** The map stores SHA-256 hashes of every carrier used. During decoding, `decoder` verifies the live SHA-256 of provided carriers to prevent reconstruction using wrong or modified file versions.

---

### 4. Robust Steganography Suite
Inev can hide its maps inside other files using two advanced methods:
*   **Append (Overlay):** Stealthily attaches the map to the end of any file (works for images, videos, executables).
*   **Robust Randomized LSB:** Hides data inside the Least Significant Bits of BMP images.
    *   **Xorshift32 PRNG:** Bits are not stored in order; they are scattered across the image based on a pseudo-random sequence generated from your **password**.
    *   **Tail-Noise Resistance:** A dedicated `Size Field` in the header prevents extraction errors caused by file-end garbage.

##  CLI Usage & Flags

###  Encoder Syntax
```bash
./encoder -s <secret1> [<secret2>...] -c <carrier1> [<carrier2>...] [OPTIONS]
```

| Flag | Name | Description |
| :--- | :--- | :--- |
| `-s` | **Secret** | Path to the file(s) you want to hide (supports multiple). |
| `-c` | **Carrier** | Path to the source pattern file(s) (supports multiple). |
| `-x` | **Strict Mode** | **No-Literal Guarantee**. Fails if 100% of the secret cannot be covered by the carriers. |
| `-a` | **Analyze Mode** | Runs coverage check and displays statistics without generating a `map.txt` file. |
| `-H` | **Hunter** | **Multicore Search**. Scans a directory and ranks files by how well they match your secret. |
| `-e` | **Append** | Embeds the encrypted map as a hidden overlay at the end of a host file. |
| `-l` | **Robust LSB**| Scatters the map bits invisibly inside a BMP image using password-seeded randomization. |

---

###  Decoder Syntax
```bash
./decoder -m <map_file> -c <carrier1> [<carrier2>...]
```

| Flag | Name | Description |
| :--- | :--- | :--- |
| `-m` | **Map File** | Path to `map.txt` or a stego host file containing the embedded map. |
| `-c` | **Carrier** | Path to the carrier file(s) required for reconstruction (must match original SHA-256). |

---

##  Practical Examples

### Scenario A: Hiding a Secret with Carrier Streaming
Encode a secret file using a large video or ISO as a carrier:
```bash
./encoder -s backup.zip -c movie.mp4
```
*To reconstruct the secret:*
```bash
./decoder -m map.txt -c movie.mp4
```

---

### Scenario B: Ghost Map (Strict Mode `-x`)
Ensure NO part of your passwords file is stored as literal bytes in the map:
```bash
./encoder -s passwords.txt -c game_data.iso -x
```

---

### Scenario C: Carrier Compatibility Check (`-a`)
Test how well your carriers cover a secret before generating a map:
```bash
./encoder -s secret.bin -c video1.mp4 video2.mkv -a
```

---

### Scenario D: Invisible Image Steganography (LSB `-l`)
Hide a secret archive inside a BMP image, scattered using a password-seeded sequence:
```bash
./encoder -s backup.zip -c movie.mp4 -l family_photo.bmp
```
*To extract and reconstruct:*
```bash
./decoder -m family_photo_stego.bmp -c movie.mp4
```

---

### Scenario E: Finding the Best Carrier (`-H`)
Scan a directory to find files that have high pattern coverage for your secret:
```bash
./encoder -s secret.bin -H /home/user/Downloads/
```
